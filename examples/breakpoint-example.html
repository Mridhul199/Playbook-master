The matrix

What scales, what holds, what dies.

A property either grows with the viewport, locks at a value, or disappears entirely above the cap. No "it depends" — the matrix decides.

Scales

Grows with viewport — bounded
  • Container — grows 960 → 1280, then locks
  • Section padding — 24 → 32 → 40 → 48
  • Hero type — 36 → 48 → 56 → 64
  • Page gutters — 16 → 24 → 32
  • Image hero — fills container but never beyond
  • Card grid gap — 12 → 16 → 20

Holds

Constant across all tiers
  • Body text — 14px (15ch–75ch comfortable)
  • Click targets — 36px min, 44px primary
  • Input field width — 320–480px never wider
  • Table column widths — designed, not fluid
  • Form column width — 560px (one) / 720px (two)
  • Modal widths — 440 / 560 / 720 (DLS)
  • Border radius, shadows, ring — token-fixed

Dies

Disallowed at any breakpoint
  • Full-bleed body content — text edge-to-edge
  • Stretched tables — column padding > content
  • 100% fluid forms — inputs wider than 50ch
  • Edge-pinned primary CTA — Fitts penalty
  • Floating action buttons — chrome-only
  • Cropped hero focals — never sacrifice subject
  • "Stretch to fill" mode — no user toggle for this

The step-down ladder

Components shrink in 8s.

When the viewport drops below 1280, components step down one size — never the layout. Compact treatment begins at 1024 and persists at 720 (same tokens, same sizes). Spacing and heights step in strict multiples of 8; typography rides a type-scale ratio (rationale below). At 720, the table absorbs viewport pressure through horizontal scroll or column hiding — the components themselves don't shrink further.

The 8-step rule

Spacing, padding, and component heights step in multiples of 8 (8, 16, 24, 32…). A 48px button drops to 40, not 44. Typography is the exception — it uses the DLS type scale (a perceptual ratio), not arithmetic 8s. See the rationale below.

One step, two tiers

1280+ uses base sizes. At 1024, every component drops one size — button 48→40, row 72→56, padding 24→16, container radius 32→16, side-nav collapses to a 56 icon rail. 720 holds the same compact tokens; the table absorbs the squeeze through scroll or column hiding.

The accessibility floor

Click targets never go below 24×24 (WCAG 2.5.5 AA). Touch targets stay ≥44 (AAA / Apple HIG). Body text holds at 14px. The system stops stepping when the floor is reached.

Why typography doesn't follow the 8-step rule

Spacing and component heights are arithmetic — 8, 16, 24, 32. Predictable additive steps work because the eye perceives spatial change linearly. Pixels of empty space are pixels of empty space.

Typography is perceptual — the eye reads size on a logarithmic curve. A jump from 14→16 (delta 2) reads as the same "step" as 24→28 (delta 4) or 48→56 (delta 8). To make hierarchy feel consistent, type scales use a ratio instead of a fixed delta. DLS uses a perceptual scale with steps that map roughly to a 1.2–1.33 ratio — same perceived "one step" across the whole range.

Accessibility consequence: WCAG SC 1.4.4 requires text to remain functional when resized to 200%. A ratio-based scale preserves the relative hierarchy at any zoom level. A flat 8px delta would either crush small text faster than large text shrinks (proportion breaks) or leave large headings imperceptibly different (no hierarchy). The type scale prevents both failures.

The thesis

White space is a feature, not a bug.

On a 2560px monitor, our content sits in a 1440px lane. Half the screen is "empty." That emptiness is doing real work — protecting reading distance, reducing eye travel, keeping CTAs within thumb-reach of the cursor.

✕ Naive approach

Fluid stretch to 100%

Table columns explode to 200ch. Forms become unscannable. Primary CTA drifts to the edge — Fitts's law penalty kicks in. Eye saccades blow past comfortable reading width.

The rationale

Nine UX laws behind the choice.

Tap any card to read the full justification. Every law is independently sufficient. Stacked, they make the centered-and-capped approach non-negotiable.

1

Fitts's Law

Paul Fitts · 1954

Time to acquire a target is proportional to distance, inversely proportional to size. T = a + b·log₂(D/W + 1)

How it applies
On a 4K screen, a primary CTA pinned to the right edge sits ~1400px from a cursor at center. That's a measurable ~200–400ms penalty per click per user, per task. By capping content at 1440, the worst-case cursor travel is bounded — a primary action on a 2560px screen behaves identically to one on a 1440px screen.
2

Hick's Law

Hick & Hyman · 1952

Decision time grows logarithmically with the number of choices visible. T = b·log₂(n + 1)

How it applies
A fluid table on 4K shows 12+ rows fully on screen at once. Each row is an implicit choice. Capping at 1440 keeps comfortable viewport density (~6–8 actionable rows) — ops users act faster on a focused list than on a wall of data.
3

Law of Proximity

Gestalt · Wertheimer 1923

Objects placed close together are perceived as related. Distance breaks the perceptual group.

How it applies
A summary card and its sub-metrics belong together. When fluid, they drift apart on wide screens and stop reading as a group. Capping the container preserves the spatial relationship — designers control proximity, the viewport doesn't.
4

Optimal Line Length

Bringhurst · Tinker

Comfortable reading: 45–75 characters per line. Beyond ~90ch, the eye loses the next line on return.

How it applies
Invoice descriptions, customer notes, error messages — any body text wider than ~75ch (≈680px at 14px Inter) becomes painful. A 2400px-wide table cell with full description text is functionally unreadable. The cap protects every text-bearing surface.
5

Foveal Vision

Human visual system

Only ~5° of the visual field is in sharp focus (~3cm wide at typical viewing distance). Everything else requires a saccade.

How it applies
At a typical 60cm viewing distance, the eye's focal "spotlight" is roughly 5cm wide on screen. Information spread across a 70cm wide 4K monitor forces constant head-and-eye repositioning. Cap = fewer saccades = lower visual fatigue across a 6-hour finance ops shift.
6

Miller's Law

George Miller · 1956

Working memory holds ~7±2 chunks. Beyond that, retention collapses without chunking strategies.

How it applies
A 4K dashboard could show 12 KPI cards in one row. A user reviewing collection performance can't hold that in working memory — they'll scan past or compare incorrectly. Three to five cards per row, capped width, is a designed constraint that respects the cognitive ceiling.
7

Jakob's Law

Jakob Nielsen · 2000

Users spend most of their time on other sites and expect yours to work the same way.

How it applies
Our users live in Tally, Zoho, Razorpay dashboard, GSP portals, Excel, Gmail. Every one of those caps content. If a DLS-based product stretched, users would feel the design is "off" without being able to name why. Conforming to the prevailing pattern is the lowest-cost route to perceived quality.
8

Tesler's Law

Larry Tesler · ~1980

Conservation of complexity: every system has irreducible complexity. Someone must absorb it — the system or the user.

How it applies
Fluid layouts push complexity onto users — "where did the button go?", "why is the table wider here?". A capped layout absorbs that complexity in the design system: predictable lanes, repeatable patterns. The user never thinks about layout. They think about getting paid.
9

Aesthetic-Usability Effect

Kurosu & Kashimura · 1995

Users perceive aesthetically pleasing interfaces as more usable, more trustworthy, and forgive minor friction more easily.

How it applies
Generous, controlled white space reads as premium. For a fintech product handling crores of receivables, perceived quality directly drives trust — and trust drives the willingness to enter API keys, GST numbers, and bank credentials. The "empty" 4K margins are doing trust-building work.
