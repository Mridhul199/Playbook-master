Root cause

Semantic <table> vs <div role="table">.

The current component is built from divs with partial ARIA, which is a valid pattern but a more demanding one — every behavior that a native <table> would give for free has to be re-created by hand. Some are in place; the rest are listed below.

✕ Current approach

Div tree with partial ARIA

Headers and rows have role attributes, but the container, head/body wrappers, and individual cells are missing them. Assistive tech sees a grouping of rows rather than a navigable table — the column-to-cell association is lost.

// Table.tsx — line 385, 477, 506
<div> // no role
  <div> // head wrapper — no role
    <div role="columnheader">Customer</div>
  </div>
  <div> // body — no role
    <div role="row">
      <div>Ravi Menon</div> // no role
    </div>
  </div>
</div>
✓ Recommended

Semantic HTML + minimal ARIA

Native <table>, <thead>, <tbody>, <th>, <td>, <caption> give browsers and assistive tech the structure they expect. ARIA fills only the dynamic gaps — sort state, expanded rows, selection.

// Refactored
<table>
  <caption>Receivables awaiting action</caption>
  <thead>
    <tr>
      <th scope="col" aria-sort="ascending">Customer</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Ravi Menon</td>
    </tr>
  </tbody>
</table>

If a semantic refactor isn't feasible right now, the div-table needs every missing role and ARIA attribute filled in. The 17 findings below show exactly what's missing.

For the designer

Manual verification — 6 checks, ~20 minutes.

About 60% of accessibility can't be automated. Run these in the browser with the Table rendered. Each check has the exact tool, steps, and what to look for. Mark pass/fail and add notes as you go — your record sits inside the playbook itself.

1. Keyboard sweep

WCAG 2.1.1 · 2.4.3
~4 min
  1. Tool: Keyboard only. Disable your mouse / cover your trackpad.
  2. Action: Click into the page. Press Tab through the table — header → checkboxes → sortable columns → row actions → pagination.
  3. Look for: Every interactive element receives focus. Focus always visible. Order matches visual order. No "dead" stops. No traps.
  4. Sort: Press Space on a sortable header. Does it sort? (Currently no — only Enter works.)
  5. Row click: Press Enter on a clickable row. Does it trigger? (Currently no — empty onKeyDown.)

2. Screen-reader walkthrough

WCAG 1.3.1 · 4.1.2 · 4.1.3
~6 min
  1. Tool: macOS — Cmd+F5 to start VoiceOver. Windows — install NVDA (free), Ctrl+Alt+N.
  2. Action: Navigate to the table. Use Tab + arrow keys to move through.
  3. Listen for: Does it announce "table"? (Probably not — current code uses divs.)
  4. Listen for: Sortable headers — do they say "sorted ascending/descending"?
  5. Listen for: Pin button — "Pin column, button" or just "button"?
  6. Listen for: Expand row — does SwitchButton say "Expand row, button, collapsed/expanded"?
  7. Listen for: Empty state — when the table has no records, is "No records found" announced?

3. Focus visibility

WCAG 2.4.7 · 2.4.11
~2 min
  1. Tool: Keyboard only.
  2. Action: Tab through every interactive element — checkbox, sort header, pin, expand, row, action buttons, pagination.
  3. Look for: Focus ring always visible. Distinguishable from non-focused (≥ 2px / 3:1 contrast).
  4. Look for: Pin button — when focused, is it actually visible? (Currently invisible until parent hover.)

4. Zoom & reflow

WCAG 1.4.4 · 1.4.10
~3 min
  1. Tool: Browser zoom. Cmd++ / Ctrl++.
  2. Action: Zoom to 200%. Then 400%.
  3. Look for: All content readable. No text cut off.
  4. Look for: Buttons/icons still tappable. Pagination still works. Sticky header still functions.

5. Touch / pointer

WCAG 2.5.1 · 2.5.5
~2 min
  1. Tool: Chrome DevTools → Device toolbar (Cmd+Shift+M). Pick a touch device.
  2. Action: Try to tap Pin icon, rows, sort headers.
  3. Look for: Pin button — visible without hover? (Currently no.)
  4. Look for: All targets ≥ 24×24 (AA) or 44×44 (AAA / Apple HIG).
  5. Look for: No accidental triggers from adjacent buttons.

6. Color-only state check

WCAG 1.4.1
~2 min
  1. Tool: macOS — System Settings → Display → Color Filters → Grayscale. Or Chrome DevTools → Rendering → Emulate vision deficiencies → Achromatopsia.
  2. Action: Apply grayscale, look at the table.
  3. Look for: Sort direction — can you still tell? (Currently the indicator is just an icon fill change.)
  4. Look for: Failed/overdue states — communicated by anything other than color?
  5. Look for: Selection, focus — all still distinguishable?
For the dev

Line-by-line fixes.

Every critical finding mapped to file + line range + the exact code change. Copy-paste ready.

F-01 · Missing table semantics

Table.tsx:385, 477, 506 · WCAG 1.3.1, 4.1.2 · Critical
Fail
Current
// container
<div ref={effectiveRef}>
  // head
  <div>
    <div role="columnheader">...</div>
  </div>
  // body
  <div>
    <div role="row">
      <div /* no role */>cell</div>
    </div>
  </div>
</div>
Fix (minimum ARIA)
<div role="table" aria-label="Receivables">
  <div role="rowgroup">
    <div role="row">
      <div role="columnheader">...</div>
    </div>
  </div>
  <div role="rowgroup">
    <div role="row">
      <div role="cell">cell</div>
    </div>
  </div>
</div>
Better: refactor to semantic <table><thead><tbody><th scope><td>. CSS can still drive visual layout via display:grid. Browsers + SRs get table semantics for free.

F-02 · Sort missing aria-sort + Space key

Table.tsx:428–434 · WCAG 2.1.1, 4.1.2 · Critical
Fail
Current
<div
  onKeyDown={(e) => {
    if (e.key === 'Enter') {
      handleSortingChange(column);
    }
  }}
  tabIndex={column.sortable ? 0 : -1}
  role="columnheader"
  /* no aria-sort */
>
Fix
<div
  onKeyDown={(e) => {
    if (e.key === 'Enter' || e.key === ' ') {
      e.preventDefault();
      handleSortingChange(column);
    }
  }}
  tabIndex={column.sortable ? 0 : -1}
  role="columnheader"
  aria-sort={
    column.key === sortField
      ? (order === 'asc' ? 'ascending' : 'descending')
      : 'none'
  }
>
Bonus: wrap the sortable header content in a <button> — browsers handle Space + Enter automatically. aria-sort lives on the columnheader.

F-03 · Clickable row has empty onKeyDown

Table.tsx:484–486 · WCAG 2.1.1 · Critical
Fail
Current
<div
  onClick={rowClickable?.isRowClickable
    ? (e) => rowClickable.rowClickHandler(e, rowItem)
    : undefined}
  tabIndex={rowClickable?.isRowClickable ? 0 : -1}
  role="row"
  onKeyDown={() => {}}
>
Fix
<div
  onClick={...}
  tabIndex={rowClickable?.isRowClickable ? 0 : -1}
  role="row"
  onKeyDown={(e) => {
    if (!rowClickable?.isRowClickable) return;
    if (e.key === 'Enter' || e.key === ' ') {
      e.preventDefault();
      rowClickable.rowClickHandler(e as any, rowItem);
    }
  }}
>
Keyboard users currently get a focusable row that does nothing on Enter or Space. Critical AA failure.

F-04 · Pin button: no label, invisible to keyboard

Table.tsx:355–381 · WCAG 4.1.2, 2.4.7, 2.5.5 · Critical
Fail
Current
<button
  type="button"
  className="... invisible ..."
  onClick={...}
  /* no aria-label */
>
  <PinIcon className="h-5 w-5" />
</button>
Fix
<button
  type="button"
  className="opacity-0 focus-visible:opacity-100 group-hover:opacity-100"
  onClick={...}
  aria-label={isPinned ? "Unpin column" : "Pin column"}
  aria-pressed={isPinned}
>
  <PinIcon aria-hidden="true" />
</button>
Two fixes: aria-label gives it a name. focus-visible:opacity-100 makes it appear on keyboard focus too. Also bump PinIcon to 24×24 to clear WCAG 2.5.5 AA.

F-05 · SwitchButton: no label, no aria-expanded

SwitchButton.tsx:22–44 · WCAG 4.1.2 · Critical
Fail
Current
<button
  type="button"
  className={buttonBaseClasses}
  onClick={handleColumnExpand}
  /* no aria-label */
  /* no aria-expanded */
>
  {isActive
    ? <ChevronUpIcon />
    : <ChevronDownIcon />}
</button>
Fix
<button
  type="button"
  className={buttonBaseClasses}
  onClick={handleColumnExpand}
  aria-label={isActive ? "Collapse row" : "Expand row"}
  aria-expanded={isActive}
  aria-controls={`row-content-${rowIndex}`}
>
  {isActive
    ? <ChevronUpIcon aria-hidden="true" />
    : <ChevronDownIcon aria-hidden="true" />}
</button>
aria-controls requires matching id on the expanded content (Table.tsx:553).

F-06 · Empty state has no live region

Table.tsx:564–566 · WCAG 4.1.3 · Critical
Fail
Current
<div className="...">
  No records found
</div>
Fix
<div
  className="..."
  role="status"
  aria-live="polite"
>
  No records found
</div>
When filters reduce rows to zero, sighted users see "No records found". SR users hear nothing without a live region.

F-07 · Sort indicator color-only

Table.tsx:449–453 · WCAG 1.4.1 · Serious
Fail
Current
<ArrowIcon className={`...
  ${order === 'asc' && sortField === column.key
    ? 'last:[>path]:fill-icon-icon' : ''}
  ${order === 'desc' && sortField === column.key
    ? 'first:[>path]:fill-icon-icon' : ''}
`} />
Fix
<ArrowIcon
  className={...}
  aria-hidden="true"
/>
// Sort state already on parent via aria-sort (F-02).
// Optional belt-and-suspenders:
{column.key === sortField && (
  <span className="sr-only">
    , sorted {order === 'asc' ? 'ascending' : 'descending'}
  </span>
)}
Once F-02's aria-sort is in place, the visual icon becomes redundant for SR users — mark aria-hidden.
