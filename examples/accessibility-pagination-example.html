Overview

Three failures trace to one cause.

Pagination is a list of buttons inside a navigation landmark. The current code treats it as a row of styled divs — one structural choice that cascades into three categories of assistive-tech failure. Reverse the choice and most findings dissolve.

1 · Semantics

Page numbers are <div> elements with click handlers. No role="button", no <nav> landmark, no aria-current on the active page. Screen readers report a list of text rather than a navigation control.

2 · Keyboard

Prev / Next are real <button>s but carry tabIndex={-1}, removing them from the tab order entirely. Page-number divs aren't focusable at all. A keyboard-only user can't move between pages.

3 · Announcements

Active page uses border color only — no aria-current. The "Result 1 – 10 of 100" counter updates silently. After a page change, assistive tech says nothing about which page is now active or how the result set changed.

Single root cause, additive fix

Six of the eight code findings resolve once page numbers become real <button>s inside a <nav aria-label="Pagination"> landmark, with aria-current="page" on the active item and a role="status" live region on the counter. No layout change, no visual redesign — only structural and ARIA additions.

Effort: ~1 day of focused dev work. Risk: low (the visual output is unchanged). Validation: the manual checklist below covers what automation can't verify.

The shape of the fix

Current

Divs with cursor:pointer

// Pagination.tsx — current
<div className="... cursor-pointer ...">
  {page}
</div>

<button tabIndex={-1} disabled={...}>
  Previous
</button>
Fix

Nav of buttons with aria-current

// Pagination.tsx — fix
<nav aria-label="Pagination">
  <button
    aria-label="Go to page 3"
    aria-current="page">
    3
  </button>
</nav>

Code-level fixes

Eight findings. File, line, diff.

Each card has the current code (left, red highlights on the broken bits) and the fix (right, green highlights on the change). Address F-01 through F-04 first — they block AA.

F-01 · Page item rendered as div

Pagination.tsx:77–84 · WCAG 4.1.2, 2.1.1 · Critical
Fail
Current
type === 'page' ? (
  <div
    className={`${activePage === page-1
      ? '!border-border-dark-hover !pointer-events-none'
      : ''}
      label-medium ... cursor-pointer ...`}
  >
    {page}
  </div>
) : element;
Fix
type === 'page' ? (
  <button
    type="button"
    aria-label={`Go to page ${page}`}
    aria-current={activePage === page-1
      ? "page" : undefined}
    className={...}
  >
    {page}
  </button>
) : element;
Bonus — drop !pointer-events-none on the active state; use the aria-current attribute as the disable signal and rely on consuming code to skip the no-op page change.

F-02 · tabIndex={-1} on Prev / Next

Pagination.tsx:141, 162 · WCAG 2.1.1, 2.4.3 · Critical
Fail
Current
<button
  type="button"
  disabled={activePage === 0}
  tabIndex={-1}
>
  <LeftArrow />
  <span>Previous</span>
</button>
Fix
<button
  type="button"
  disabled={activePage === 0}
  aria-label="Previous page"
>
  <LeftArrow aria-hidden="true" />
  <span>Previous</span>
</button>
Why it broke — tabIndex={-1} was likely added to suppress double-focus when rc-pagination also focused the wrapping element. Resolve by letting rc-pagination's itemRender render the button directly, not wrapped.

Pagination.tsx:87–89 · WCAG 1.3.1, 2.4.1 · High
Fail
Current
<div
  className={`flex w-full items-center
    justify-between px-6 py-4 ${wrapperClass}`}
>
  ...
</div>
Fix
<nav
  aria-label="Pagination"

F-04 · Result counter not announced

Pagination.tsx:105–107 · WCAG 4.1.3 · High
Fail
Current
<div className="label-medium ...">
  Result: {starting} - {activeElements} of {totalItems}
</div>
Fix
<div
  role="status"
  aria-live="polite"
  aria-atomic="true"
  className="label-medium ...">
  Showing {starting}–{activeElements} of {totalItems}
</div>
Why — page-change rerenders this text, but without a live region the AT user never hears it. polite queues the announcement after the current speech.

F-05 · Ellipsis is a clickable div

Pagination.tsx:119–128 · WCAG 4.1.2, 2.1.1 · High
Fail
Current
jumpPrevIcon={
  <div className="... cursor-pointer ...">
    ...
  </div>
}
Fix
jumpPrevIcon={
  <button
    type="button"
    aria-label="Jump back 5 pages"
    className="...">
    <span aria-hidden="true">…</span>
  </button>
}
Apply to both — jumpPrevIcon and jumpNextIcon. Hide the literal "…" from AT and give the button an action-oriented name.

F-06 · No focus-visible styles

Pagination.tsx (all interactive) · WCAG 2.4.7 · High
Fail
Current
className="... rounded px-1
  hover:!bg-fill-pressed"
// no focus rule
Fix
className="... rounded px-1
  hover:!bg-fill-pressed
  focus-visible:outline-2
  focus-visible:outline-orange
  focus-visible:outline-offset-2"
Bonus — centralize the focus utility in tailwind.config as a @layer components rule so every interactive DLS atom inherits it.

F-07 · PageItems dropdown missing Space key + aria-expanded

PageItems.tsx:36–50 · WCAG 4.1.2, 2.1.1 · Medium
Partial
Current
const handleKeyDown = (e) => {
  if (e.key === 'Enter') toggleDropdown();
  // Space key missing
};

<div
  role="button"
  tabIndex={0}
  // no aria-expanded
>
Fix
const handleKeyDown = (e) => {
  if (e.key === 'Enter' || e.key === ' ') {
    e.preventDefault();
    toggleDropdown();
  }
};

<button
  type="button"
  aria-expanded={isOpen}
  aria-haspopup="listbox"
>
Better — replace role="button" on a div with a real <button>. You get Space + Enter + form semantics for free, no keyboard handler needed.

F-08 · Active state communicated only by border color

Pagination.tsx:78 · WCAG 1.4.1 · Medium
Partial
Current
activePage === page-1
  ? '!border-border-dark-hover
     !pointer-events-none !border'
  : ''
Fix
activePage === page-1
  ? 'border border-border-dark-hover
     bg-fill-pressed font-semibold
     text-text-dark'
  : ''
Why — 1.4.1 forbids signalling state by color alone. Adding background fill + bold weight gives color-blind and low-vision users a second signal. Combined with aria-current="page" (F-01), assistive tech also gets the cue.
Anti-patterns

Three habits to stop repeating across DLS.

These are not Pagination-specific. They appear anywhere a designer reaches for a div when a button is the right answer.

✕ Anti-pattern

div with onClick

A clickable <div> has no role, no keyboard, no focus, no AT announcement. CSS cursor:pointer is a visual lie.

Fix — use <button type="button">. Style with appearance:none. You get every accessibility behavior for free.
✕ Anti-pattern

tabIndex={-1} on a visible control

If a control is visible and interactive, it must be reachable by keyboard. -1 is for programmatically focused elements only (e.g. headings after route change).

Fix — remove tabIndex. If something else focuses-twice, fix the root cause, don't hide the button.
✕ Anti-pattern

State by color alone

A 1px border colour is the only signal of "this is the current page." Color-blind users, low-vision users, and screen readers all miss it.

Fix — pair the visual change with a second signal: background fill, font-weight bump, or icon — plus aria-current.
